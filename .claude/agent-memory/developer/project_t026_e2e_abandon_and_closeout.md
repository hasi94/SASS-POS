T-026 (FP-206, tenant provisioning) closed out across steps 15-18 in one session, after steps 1-14 shipped across three earlier sessions (see [[project_t026_create_owner_verify_activate]], [[project_t026_reserve_identity_select_server]], [[project_t026_provisioning_kernel_layer]]).

**Where the end-to-end test had to live.** `deptrac.yaml`'s `Package_Platform_Tests` layer may only reach `Package_Platform`/`Package_Contracts`/`Package_Kernel*` - not `Package_Auth`. Step 15's test needs `Flexipos\Auth\Features\Login\LoginHandler` for the login assertion, so it lives in `modules/host/tests/Feature/ProvisionTenantEndToEndTest.php` (the `HostTests` layer is the one layer already granted both). Follow the existing `require_once __DIR__.'/../../../../packages/auth/tests/Support/auth-fixture.php';` convention from `QaAuthHttpSurfaceTest.php` for the signing-key fixture.

**Generic crash-and-resume, without touching any step class.** `RecordingTenantDatabaseProvisioner` on a `sqlite` server `touch()`es a bare relative filename in the process's cwd, and `write_mapping`/`Tenancy` carry that same bare name forward - so the whole end-to-end test must `chdir()` into a throwaway directory per test (mirroring `RecordingTenantDatabaseProvisionerTest`'s own shape) and restore cwd in `afterEach`. For "a crash right after each of the eleven steps, then a resume completes", `Container::extend($stepClass, fn ($built) => new Decorator($built))` works on any class name whether bound or not: a decorator that runs the real step to completion and then throws once (a static `$armed` flag) simulates "crashed right after this step committed" without any production file knowing about it, and the resumed attempt's fresh resolution hits the same decorator with the arm spent, falling through to the real (already-idempotent) step.

**The sole-writer scan recurs per new writer.** `QaPlatformSourceRulesTest.php`'s `tenants.status` sole-writer check (`qaPlatformOtherWriters('tenants', 'status', [...])`, no `$directories` override = scans the whole real source tree) is a standing gate, not a one-time fix: session 3 widened it for `Activate.php`; this session's `AbandonProvisioningHandler.php` (which also legitimately writes `tenants.status = 'archived'`) tripped it again and needed the same widening, by name, in the same array literal. Any future file that writes `tenants.status` will trip this the same way - check this test first, not last.

**Final gate (2026-11-07, this branch).** `composer check`: lint passed, PHPStan "No errors", Deptrac 0 violations, tests 13 failed / 25 skipped / 2980 passed (20603 assertions), 815s. The 13 are the exact pre-existing baseline from session start (`ModulesEnvParsingTest`, `QaHealthProbeResilienceTest`×2, `QaModuleNameValidationTest`×3, `QaModuleRegistryContractTest`×6 - passes in isolation, order-dependent flake - and `QaVocabularyRenameSweepTest`×1, which flags this project's own `.claude/agent-memory/` files plus a pre-existing `frontend/package-lock.json` entry). None are T-026's.

**Why abandon doesn't call each step's own `compensate()` for the real work.** Every one of the eleven steps' `compensate(RunContext): ?string` returns `null` on purpose (stated in each one's own docblock) - `dropUser()`, `forget()` and the two archival writes cross package/connection lines no single step owns, and D-21 forbids a `DROP DATABASE` existing anywhere outside test infrastructure, so there is nothing a per-step `compensate()` could safely do with the database either. `AbandonProvisioningHandler` does all of it directly, reading every fact from the run's own journal (`ProvisioningRuns::stepOutput()`), never from configuration.
