## Reviewer round 2 close-out (R-2)

- **R-2 (critical, fixed by `dev`, independently mutation-tested by `qa`):** W-8's own fix (round 1) made `TenantStatusSync::reconcile()`'s no-op branch overwrite `suspension_reason` whenever the computed trigger differed from the current sentinel reason — but it never checked whether the computed trigger was itself null. `CommercialStatus::target()`'s table has exactly two rows that return a null trigger: row 0 (protected statuses, or an already-suspended tenant whose reason is not one of this task's own sentinels — both already excluded by the surrounding conditions, the first because its target status is never `suspended`, the second because its reason is never in `SENTINELS`) and row 8 ("no subscription row" — reached only when `CurrentSubscription::for()` returns null, confirmed exhaustively: `SubscriptionStatus::ALL`'s six values map 1:1 onto rows 1/2/4/5/6/7, each of which has a non-null trigger, so row 8 is reachable only with no subscription row at all). A tenant suspended for `licence_lapsed` with **no subscription row**, once its platform licence becomes valid again, hits row 8: target status unchanged (still `suspended`), trigger `null`. Without the extra guard, the W-8 branch read that as "a different sentinel has superseded this one" and overwrote `suspension_reason` with `null` — and a null reason reads as "not ours" (D-16), so the suspension could then never be auto-lifted. **Fix:** added `&& $target['trigger'] !== null` to the W-8 guard's condition, immediately after `$target['status'] === TenantCommercialStatus::SUSPENDED`.
- **Enumeration check (this round's own verification, not just re-reading `dev`'s fix):** walked every one of `CommercialStatus::target()`'s 9 return points by hand against the new guard's three conditions (`target status === SUSPENDED`, `trigger !== null`, `reason is a sentinel`) to confirm row 8 is the *only* dangerous null-trigger combination and that the new clause neither under- nor over-guards: row 0a (protected) never reaches `SUSPENDED` as a target, so it was always safe regardless of the trigger check; row 0b (manually suspended, non-sentinel reason) was already excluded by the existing sentinel check with or without the new clause; rows 1–7 never return a null trigger. No other row needed covering.
- **Mutation-tested by `qa` (not accepted on `dev`'s say-so):** removed `&& $target['trigger'] !== null` from the guard, ran `TenantStatusSyncTest.php` standalone — the new R-2 test went red exactly as predicted (`Failed asserting that null is identical to 'licence_lapsed'.`, at the `suspension_reason` assertion), the other 3 tests in the file stayed green (1 failed, 3 passed, 24 assertions). Restored the clause, re-ran the same file: 4 passed, 25 assertions, all green including the R-2 case. The mutant is caught precisely by the scenario the test claims to cover, not by some unrelated side effect.
- **New test (`packages/platform/tests/Support/TenantStatusSyncTest.php`, added by `dev`):** seeds a tenant suspended with `suspension_reason: licence_lapsed` and **no subscription row at all**, gives it a valid platform licence, calls `reconcile()`, and asserts the trigger returned is `null`, `status` stays `suspended`, `suspension_reason` stays `licence_lapsed`, and zero new `tenant_status_synced` audit rows are written. Helpers used (`PlatformSeed::tenant`/`licence`/`connection`/`tenantRow`/`auditRows`) all exist with matching signatures; no subscription is seeded for this tenant, so `CurrentSubscription::for()` genuinely returns null and row 8 is genuinely exercised, not simulated.
