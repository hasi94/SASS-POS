# Plan: T-037 Till application: product grid, scanning, cart, payment, refund (frontend, mock API)

Spec: `docs/specs/T-037-till-application.md` (AC-1 to AC-92). Decisions: `docs/decisions/T-037-till-application.md`
(D-1 to D-30). Backend semantics: `docs/specs/T-030-sales.md` rev 8. Architect decisions made here are numbered
**P-1 to P-14** (below) and are the lead's to log; questions for `ba` are at the end.

## Approach summary

Frontend only, online only, against an in-memory mock. Two layers, split the way T-025 already splits them:

1. **`@flexipos/shared`, two new self-contained folders** (no existing shared file is edited except
   `public-api.ts`, append-only):
   - `lib/sales/`: the typed contract (one folder, every call, branded decimal strings, T-030 column
     names), the closed `SalesRefusalCode` union with its wire mapping, `SalesApi` (the only HTTP caller),
     the two ports `LinePricer` and `BarcodeResolver` as injection tokens whose default factory is the
     server-backed adapter, the single `decimal-string.ts` helper, and the checked-in JSON fixtures.
   - `lib/sales-mock/`: a **second, development-only interceptor** (`salesMockInterceptor`) that sits
     in front of the untouched auth mock in `pos`'s `environment.development.ts` only. In-memory state,
     deterministic clock and ids, BigInt arithmetic confined to `mock-decimal.ts`, a sentinel string for
     the production-bundle grep.
   - `lib/ids/ulid.ts`: the in-repo ULID utility (D-12).
2. **`pos`, `projects/pos/src/app/till/**`**: the lazily loaded `TillPage` becomes the sale screen.
   Component-scoped signal stores (provided on `TillPage`, so nothing survives a sign-out), one dialog
   outlet, one keymap file, one refusal catalogue, standalone `OnPush` components.

The work is chunked so that after **Chunk 0** (contracts, ports, decimal helper, ULID, refusal
catalogue, keymap, mock skeleton, fixture test, money-rules scan, till scaffold with every component
file stubbed), **Track A** (mock write side, approvals, void, refund, docs) and **Track B** (shift, grid,
scan, cart, customer, payment, hold/recall) touch disjoint files. A short **Chunk Z** joins them.

## Alternatives rejected

- Extending the existing `mockBackendInterceptor`: T-036 extends it in parallel (catalog CRUD); a separate interceptor file avoids the merge and keeps the sales sentinel separate.
- `@angular/cdk` for focus trap / overlays: a new dependency for one small directive; a ~40-line in-repo focus trap is enough (AC-82). No new dependency in this plan.
- A decimal library (big.js, decimal.js): the till does no arithmetic (D-6); the mock needs only add, subtract, multiply-and-round at scale 4, which BigInt does in ~60 lines.
- A ULID package: ~40 lines in-repo with `crypto.getRandomValues`, tested (spec NFR asks for in-repo).
- Native `<dialog>.showModal()`: jsdom support is incomplete, so focus behaviour would be untestable.
- Root-level (`providedIn: 'root'`) stores: sale data would outlive sign-out inside the tab (AC-87); component-level providers die with `TillPage`.
- JSON fixtures imported statically through a hand-kept manifest: a fixture added without a manifest line would escape the contract test. Specs read the folder with `node:fs` instead (P-12).

## Architect decisions (P-n; the lead logs them, none blocks)

- **P-1 Tender contract (resolves D-8).** `AddTenderRequest = { id: Ulid; payment_method_id: string; tendered: Money; reference?: string | null }`. The type has **no** `amount` or `change_given` key, so the till cannot send them (a compile error, not a convention). The response is `AddTenderResponse = { tender: SaleTender; sale: Sale }` where `SaleTender` carries T-030's `amount`, `tendered`, `change_given`. The derivation the future route layer owes before calling T-030's `AddTender` (which takes both) is written once, as a doc comment on the type and as fixtures: `tendered <= balance_due` gives `amount = tendered, change_given = 0.0000`; `tendered > balance_due` with `allows_change` gives `amount = balance_due, change_given = tendered - balance_due`; without `allows_change` it is refused `exceeds_balance`. Replay key is the request triple `{payment_method_id, tendered, reference}`. Fixtures `sales.add-tender/success.cash-over-tender.json` (tendered 2000.0000 on balance 1250.0000 returns amount 1250.0000, change_given 750.0000) and `refused.exceeds_balance.card-over-tender.json` make the rule the conformance obligation of follow-up row 1. Refund tenders are a separate type, `RefundTenderRequest = { id; payment_method_id; amount: Money; reference? }` (positive payout; no `tendered`, matching T-030 AC-12B which stores `tendered = null`).
- **P-2 Change display.** T-030 AC-13A writes `sale.change_due` only at completion. The payment dialog shows the tender's server `change_given` as "Change" right after an over-tender; the completion screen shows `sale.change_due`. Both are server strings (reading of AC-44; Q-4 to `ba`).
- **P-3 Wire codes.** T-021 AC-10 namespaces codes (`sales.no_open_shift`, `kernel.validation_failed`, `kernel.not_found`). `refusalOf(err: ApiError): SalesRefusalCode | null` takes the first `errors[].code`, strips the `<module>.` prefix, maps `validation_failed` to `validation`, and returns it only if it is a member of `SALES_REFUSAL_CODES`; anything else is the generic case (AC-73). The mock emits namespaced codes so the till is tested against the real form.
- **P-4 Refusal facts.** A refusal that names a fact (T-030: "naming the remaining amount", "carrying the ledger's reason") carries it as `errors[0].field = <fact name>`, `errors[0].detail = <machine value>`, read with the existing `ApiError.fieldDetail()`. Table in `contract/refusals.ts`: `balance_due` → field `balance_due` (Money); `over_refund` → `refundable_quantity` (Quantity) or `refundable_amount` (Money, the AC-27B money cap); `credit_refused` → `cause`; `numbering_refused` → `cause`; `product_not_sellable` → `failed_fact`; `invalid_transition` → `status`; `unit_unresolvable`/`inherited_unit_mismatch` → `unit_code`; `in_use` → `count`; `validation` → T-021 native (field = input name, detail = message). Q-5 to `ba`.
- **P-5 HTTP statuses** (T-014 Ruling 8 precedent): 422 `validation`, 404 `not_found`, 401 unauthenticated, 403 every other refusal. Kept in `REFUSAL_STATUS` in `contract/refusals.ts`; the till never branches on status except 0 (network) and 5xx (generic).
- **P-6 Routes.** One table, `contract/calls.ts`, lists every call as `{ id, method, path(params) }`. `SalesApi` and the mock both read it, so a path cannot drift between them. Scan resolution is `POST till/scan {code}`, not a GET query: Angular `HttpParams` does not encode `+`, so a GET could not send a Code 128 code "unchanged" (AC-22), and a body keeps codes out of URLs and access logs.
- **P-7 Calls the spec needs that T-030 has no slice for** (contract marks them `@proposed`, mock implements them, follow-up rows 1/2 own them): `PUT sales/{id}/customer` (attach a customer to an existing draft; refused `sale_not_editable` once `pending_payment`, Q-1); `POST refunds/quote` (read-only quote of refund lines, so the payout can default to the server's refund total before `RefundSale`, which takes lines and tenders in one call, Q-2); a client `id` (ULID) on `POST refunds` as its idempotency key, same replay rule as `AddTender` (AC-64 retry, Q-2); server-derived `refundable_quantity` on sale lines, in the line's own unit (Q-3); `reference` (a short server-supplied reference for unnumbered sales, AC-51).
- **P-8 Terminal identity.** No request carries a branch, terminal, location or business date (AC-86). The mock reads the branch from `AuthService` inside the interceptor's injection context and derives one terminal per branch (`TRM-<branchId>`), so the wire stays exactly as the real one will be (server-resolved from the session).
- **P-9 Timeouts.** `SalesApi` applies `timeout()` (token `SALES_WRITE_TIMEOUT_MS`, default 15000) to writes and maps a timeout to `ApiError(0, ...)`, so "timeout" and "connection drop" take one path (AC-49, AC-75).
- **P-10 Ports.** `LINE_PRICER` and `BARCODE_RESOLVER` are `InjectionToken`s in `shared/lib/sales/ports.ts` with `providedIn: 'root'` factories that return the server adapters. A spec swaps either with `{ provide: LINE_PRICER, useValue: stub }`; no component or store names an adapter (AC-7). `LinePricer = { addLine(saleId, AddLineRequest): Observable<Sale>; updateLine(saleId, lineId, UpdateLineRequest): Observable<Sale>; quoteRefund(RefundQuoteRequest): Observable<RefundQuote> }`. `BarcodeResolver = { resolve(code: string): Observable<ScanResolution> }`.
- **P-11 Fixture equality.** "Byte-for-byte" is implemented as `JSON.stringify(mockBody) === JSON.stringify(JSON.parse(fixtureFile).response.body)` plus equal status: key order and every character of every value are significant, file whitespace is not (Q-6). The mock's request ids, clock and generated ids are deterministic so this holds. The later conformance run against the real server (follow-up row 3) normalises `meta.request_id`, server-generated ids and timestamps; that is noted in the README, not built.
- **P-12 Reading files in specs.** The unit-test builder bundles specs with `externalPackages: true` (checked in `@angular/build` 21.2 `runners/vitest/build-options.js`), so `import { readFileSync, readdirSync } from 'node:fs'` stays external and Vitest (Node, jsdom env) loads it at run time. `@types/node` is **not** installed, so each project that needs it gets a tiny ambient declaration file (`declare module 'node:fs' { ... }` with only the two functions used). Step 0.1 proves this before anything depends on it. Paths are relative to the workspace root `frontend/`, which is the working directory of `ng test`.
- **P-13 Runtime fixture parsing.** "Each fixture parses against the TypeScript types" is done with key-exhaustive validators: `shape<T>(spec: { [K in keyof T]-?: Check })` in `contract/testing/shape.ts`. The compiler forces a validator to list exactly the keys of its type; at run time it rejects missing keys, extra keys and wrong value kinds (money, quantity, ulid, string, nullable, enum, array, nested shape). Test-only; not exported from `public-api.ts`.
- **P-14 Money safety by type as well as by scan.** `Money` and `Quantity` are `string & { readonly __brand: ... }`. TypeScript already rejects `-`, `*`, `/`, `%` on strings; the AC-77 scan therefore concentrates on `+` (concatenation would compile), the banned functions and template expressions.

- **`node:fs` does not load in the test runner** (P-12). Step 0.1 proves it first; the fallback weakens AC-4/AC-77 completeness and goes to the lead.
- **Chunk 0 is large** (9 steps) and gates both tracks. Mitigation: it is mostly types, small helpers and stubs; Steps 0.8 and 0.9 can start once 0.3 and 0.4 are in.
- **Fixture volume** (about 27 calls, roughly 100 files) and drift between fixture and mock. Mitigation: the coverage table fails on a missing case; the recorder is local only and every fixture is hand-reviewed against the types.
- **Contract proposals the backend may not accept** (P-1, P-4, P-7). They live in one folder plus fixtures; a change is local (D-8's reversibility).
- **Component style budget** (`anyComponentStyle` error at 8 kB) and many components: keep styles in component files small and lean on `base.scss` tokens.
- **`ci.yml` edit** is asserted by a PHP test outside this task's gate; the lead runs it once (Step A5).
- **Merges with T-035/T-036** on `public-api.ts` and `README.md`: append-only.
- **Vocabulary sweep:** new frontend paths must avoid the pre-T-005 vocabulary (PHP sweep scans the working tree).
- Rollback: every step is its own commit; the feature is the lazily loaded `TillPage` plus two new shared folders. Reverting the branch restores the T-025 shell; reverting only Step A5 restores `ci.yml` byte for byte.
